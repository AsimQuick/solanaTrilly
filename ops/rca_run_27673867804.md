`redis`, `db`, `listener`, `celery-worker`, and `celery-beat` containers all

triggered the error.

## Root Cause

**Orphaned container state on the VPS from a prior deploy session.**

The VPS had stale containers named with an image-hash prefix
(`7f11953660d2_solanatrilly-web-1`) rather than the canonical project prefix
(`solanatrilly-web-1`). This naming pattern occurs when Docker Compose creates
a container under a different project-directory context than the current
invocation — for example, when a prior `docker compose` run resolved the
project name or working directory differently, resulting in container names
that include a short hash of the source image or project context rather than
the clean `-p solanatrilly` scope.

When the current deploy ran `docker compose -p solanatrilly up -d` (without
`--remove-orphans`), Compose identified the old `7f11953660d2_solanatrilly-web-1`
container as belonging to the same project but using a now-replaced image. It
stopped and removed the orphan, then started the new `97ac56a42ff1_solanatrilly-web-1`
container — but the orphaned entry persisted in Compose's internal project state,
causing a second "Starting" event for the already-removed orphan. During the
subsequent reconciliation step, Docker Compose tried to look up the freshly
started container by its full 64-character container ID
(`97ac56a42ff18ce7c65dcc654ec80f419adeb801d6fbd35820cf0a708a6436c7`) — but by
that point the Docker daemon had already removed the entry from its registry
(likely because the orphan-reconcile path killed it), producing the
`No such container` error.

## Resolution (prerequisite for AC-46.2)

Add `--remove-orphans` to the `docker compose up -d` invocation in
`.github/workflows/deploy.yml`. This instructs Docker Compose to remove any
containers that belong to the project but are not defined in the current compose
file (or have stale state from a prior project-directory context) before starting
the new stack — eliminating the orphaned-container race condition.

```diff
-  'docker compose -p solanatrilly -f /root/solanatrilly/docker-compose.staging.yml pull && docker compose -p solanatrilly -f /root/solanatrilly/docker-compose.staging.yml up -d'
+  'docker compose -p solanatrilly -f /root/solanatrilly/docker-compose.staging.yml pull && docker compose -p solanatrilly -f /root/solanatrilly/docker-compose.staging.yml up -d --remove-orphans'
```
